方向 A：AI 辅助建筑遗产调研 Agent — 产品定位与规划（v0.1 草案）

文档性质：规划草案，非已完成成果。本文件用于梳理「把现有台山骑楼立面研究工作台，重命名为一条面向遗产调研者的 AI Agent 工作流」的产品逻辑。 红线（沿用 HANDOFF §4 与简报原则）：

  1. 不虚构成果——凡标注 [现状] 为已存在能力；标注 [规划] 为待实现/待验证，不得写为已完成。
  2. 产品价值优先——每项 AI 技术都必须对应真实用户痛点，不为用而用。
  3. 现状资产不可破坏——权威文件 03-立面风格工作台/index.html 是现有工作台；本规划若落地为代码，应作为新版本（如 v0.6）演进，不回改 v0.5 口径。
  4. 个人贡献可区分——课程提供的基础代码 / AI 辅助生成代码 / 本人完成的产品设计·需求·选型·测试·迭代，须在作品集中分别标注。

0. 一句话产品定义（待定名，最终在第八阶段敲定）

「骑楼志 · AI 调研助手」：一款面向建筑/遗产研究者与文保志愿者的多模态调研 Agent——上传一批田野照片，Agent 自动完成清洗、正立面校正、构件预标注、人工复核、风格推理与谱系导出，把「几百张照片 → 可分析数据」的链路从数天压缩到数小时，且照片不出本机。

第一阶段 / 第三阶段：项目选题与产品定位

1.1 选题由来与差异化判断

为什么是「方向 A」而不是 B/C/D（来自上一轮分析）：

  • 复用 90% 现有代码（工作台 v0.5 的校正、VLM 草稿、人工复核、labelme 互通、导出、谱系），课程周期内可真正完成并演示；
  • 目标用户（研究者/志愿者/规划局）真实存在且痛点明确，能拿到访谈与测试数据；
  • 差异化来自「垂直领域知识 + human-in-the-loop」，不是又一个通用聊天机器人——符合简报「避免同质化」要求。

核心差异化一句话：通用 AI 不懂建筑构件语义、瞎答幻觉；商业标注工具只让你画框；本产品把领域知识（59 构件词表 + 5 类可解释推理）作为 AI 的约束层，用 VLM 出草稿、人做终审，既快又准，还能沉淀训练数据。

1.2 目标用户与画像

用户角色典型画像核心诉求对 AI 的信任门槛
建筑/遗产研究者（核心用户）高校师生、文保机构研究员，需系统性标注与谱系标准化、可复现、能写进论文方法高（须可解释、可复核）
文保志愿者 / 在地文化团体热爱老建筑但无专业训练，参与众包普查降低标注门槛、即时知道"这是什么"中（需要引导与纠错）
规划局 / 文旅局调研员需快速普查、出清单、建台账批量、效率、合规（数据不出域）中高（数据合规敏感）

[规划] 以上画像需在 1.5 用户研究阶段用真实访谈验证/修正。

1.3 核心痛点（含验证假设）

  1. 照片海量、人工筛选慢——一次调研几百张，挑正立面、去遮挡靠肉眼。
  • 假设 H1：自动清洗+四点校正可减少 ≥50% 预处理耗时（待实测）。
  1. 构件识别/风格判断靠资深研究者——知识无法沉淀、难以规模化、学生上手难。
  • 假设 H2：VLM 草稿 + 人工复核，比纯人工标注提速且一致性不降（待 κ 一致性验证）。
  1. 多人协作标注标准不一——同一构件不同人判读不同。
  • 假设 H3：统一词表 + 证据链展示可提升跨人一致性（待测）。
  1. 从照片到数据链路长、断点多——清洗→校正→标注→矩阵→谱系各自为战。
  • 假设 H4：Agent 单入口编排可降低使用门槛（待任务成功率验证）。
  1. 通用 AI 不懂专业语义——GPT/豆包答"巴洛克还是新古典"常幻觉。
  • 假设 H5：领域知识约束层能让 VLM 输出更准（待对比测试）。

1.4 使用场景与用户旅程（研究员一天）

晨：收到 80 张田野照 → 打开助手 → 批量导入
　　└─ Agent 自动：EXIF 转正 → 四点校正 → 遮挡/后改初筛
午：逐张看 VLM 草稿框 → 接受 / 改类 / 删框（平均每张 <30s）
　　└─ infer() 实时给"候选风格 + 证据链"
傍晚：导出 CSV/JSON（0/1 矩阵 + 谱系） → 交给谱系脚本出类型树
　　└─ 发现 3 栋无法归入 5 类 → 标记为"待讨论"，成为论文新发现

1.5 产品价值主张

价值画布（精简）：

  • 用户痛点：预处理慢、判断靠老师、标准不统一、链路断裂、通用 AI 幻觉。
  • 我们提供：本地多模态 Agent + 领域知识约束 + 人工复核闭环 + 一键导出。
  • 缺一不可的增益：① 快（自动化预处理）② 准（知识约束+人审）③ 可沉淀（人工产出即训练燃料）④ 合规（不出本机）。

1.6 差异化优势（vs 三类竞品）

对比对象它的短板我们的差异点
通用 AI 聊天（GPT/豆包/文心）无建筑构件语义、强幻觉、数据出域领域知识约束 + 不出本机 + 可复核
商业标注工具（labelme/CVAT/精灵）只画框、无自动预标注、无谱系产出内置 VLM 预标注 + 风格推理 + 谱系

1.7 技术选型理由（每个技术都对应痛点，非为用而用）

  • 为什么多模态大模型（VLM，本机 qwen3-vl:4b）：照片是核心输入；训练专用检测模型需要标注数据，而标注数据正是我们要造的——这是"鸡生蛋"困境。VLM 草稿 + 人工复核是正确的先后次序：先有标注，再谈训练。[现状] 已实测 VLM 存在 thinking 死循环、坐标漂移，因此必须 human-in-the-loop。
  • 为什么 Agent 工作流而非单点工具：用户痛点是"链路长、断点多"，Agent 把清洗→校正→预标注→复核→导出编排为单入口可追踪流水线，每步状态可见，降低门槛。
  • 为什么 human-in-the-loop（人工复核闭环）：专业场景容错极低，VLM 对专业构件类别/坐标不可靠；且人工复核产出的数据正是训练专用模型的燃料——形成数据飞轮。[现状] 工作台已有"橙色虚线草稿框→人工逐框复核→才进 infer()"机制，可直接复用。
  • 为什么隐私优先（照片不出本机、纯前端）：文保/规划用户数据合规敏感；且本机已有 Ollama，零云成本可演示。[现状] 工作台已满足"双击即用、不联网、照片不出本机"。
  • 关于 RAG（轻量 vs 正式）：[现状] 的 59 构件词表 + 5 类加权推理，本质是一层"结构化领域知识约束"，可视为轻量知识库。正式 RAG（检索文献/田野笔记/历史案例）列为 P2——MVP 阶段规则约束已够，避免"为用 RAG 而用 RAG"。

1.7.1 构件图谱：一个资产，三种用法（核心概念澄清）

你提到的「构件图谱」（每个构件配特征描述 + 示例图片）本身是结构化知识资产，它不等于 RAG，但它是能同时驱动三种 AI 技术的"原材料"：

用法是什么与 RAG 关系优先级
① 用户可浏览的参考面板点构件 → 看示例图 + 判别特征 + 易混点纯产品功能，无 AI 检索P1（产品价值独立成立）
② RAG 知识库图谱条目向量化，标注时按相似度检索最相关参考注入上下文这才是 RAG：图谱 + 向量检索 + 注入 = 检索增强P2（需后端 + 向量库）
③ 训练 / 微调数据集图谱 (图, 标签) 对用于训练专用检测器不是 RAG，是"未来自动识别"的训练集P2（飞轮终点）

一句话区分：构件图谱 = 知识；RAG = 图谱 + 检索 + 注入；训练集 = 图谱 + 标签。三者共用同一份数据，解决不同痛点——② 解决"VLM 瞎标 / 不确定"，③ 解决"全靠人工太慢"。

对 MVP 的建议：先把 ① 做出来（用户价值明确、无需检索），同时把它作为数据底座；② 的检索增强可先用"固定 few-shot 示例进 prompt"代替完整向量库（更轻），待本地后端就绪再升级为正式 RAG。

1.7.2 数据飞轮：作品集主叙事（已确认）

主线：人工复核 → 沉淀标注 → 构件图谱（结构化知识中枢）→ [RAG 辅助标注 | 训练自动识别] → 减少人工 → 更多复核沉淀。

  • 构件图谱是飞轮的枢纽：既是给人看的参考（①），也是给模型检索的知识（②），更是训练自动识别的数据（③）。
  • 这条线把"研究工具"升级为"有数据闭环的 AI 产品"，是跨专业背景最该讲透的 PM 故事：你不是用 AI 写了个工具，而是设计了一套让 AI 越用越准的机制。

第四阶段：产品设计与 MVP 规划

2.1 用户研究方案（可实际执行）

A. 访谈（规划 5–8 人）

  • 对象：2 研究者 + 2 志愿者 + 1–2 规划局/文旅 + 1–2 学生。
  • 提纲（示例）：
  1. 你一次田野调研大概拍多少张？预处理（挑图/校正）花多久？
  2. 构件判断/风格归类现在怎么做的？卡在哪？
  3. 如果 AI 先出草稿你再改，你愿意信到什么程度？什么情况下必须自己来？
  4. 数据合规上有什么限制（能否出本机/上云）？
  5. 多人协作时标准怎么对齐？
  • 产出：用户调研报告（第六阶段成果①）。

B. 测试（可用性 + 效果）

  • 用 [现状] 已有的 50 张自动校正图做 before/after：人工标注 vs Agent 辅助标注的耗时与一致性。
  • 任务成功率：给 5 张新图，用户能否在 3 分钟内完成"校正→复核→导出"。
  • 产出：AI 效果评估与测试报告（第六阶段成果⑨）。

2.2 产品定位声明（定位陈述）

对于需要做建筑遗产田野调研的研究者、志愿者与规划调研员， 我们的产品是一个本地运行的多模态调研 Agent， 它能把照片批量转成标准化、可分析的构件与谱系数据， 不同于通用 AI 聊天（幻觉、出域）和纯标注工具（只画框）， 我们的产品把领域知识作为 AI 的约束层，用人工复核保证专业准确率，且数据不出本机。

2.4 MVP 定义（课程周期内可完成的最小完整版本）

MVP = P0 全链路 + 一个 P1（Agent 进度可视化）。

  • 入口：单页面，上传一批照片 → 点"开始调研"。
  • 流程：预处理 → VLM草稿 → 人工复核（核心交互） → 风格推理 → 导出。
  • 验收：一名无专业训练的用户，凭引导在 10 分钟内完成 5 张照片的"校正→复核→导出谱系矩阵"。
  • 不做的：云端、多人实时协作、RAG、移动端、训练模型——列为路线图。

2.5 PRD 骨架（供第五阶段细化）

用户故事（示例）

  • 作为研究者，我希望批量导入照片后自动校正，以便省去手工挑图。
  • 作为志愿者，我希望 AI 先标草稿我再来改，以便无需专业知识也能参与。
  • 作为调研员，我希望导出合规的 CSV/JSON，以便直接进台账/论文。

功能需求（FR 草案）

编号需求优先级现状
FR-01支持批量导入 JPG 并 EXIF 转正P0部分
FR-02四点透视校正（自动/手动）P0现状
FR-03调用本机 VLM 出构件草稿框P0现状
FR-04草稿框人工复核（接受/改/删）P0现状
FR-05实时候选风格 + 证据链展示P0现状
FR-06导出 CSV/JSON（矩阵+谱系）P0现状
FR-07Agent 步骤状态可视化P1规划
FR-08一致性提示与争议标记P1规划

业务流程（Agent 工作流）

[导入] → [预处理: 转正/校正/遮挡初筛] → [VLM草稿预标注] 
   → [人工复核] ⇄ [infer() 风格推理+证据链] → [导出 CSV/JSON+谱系]
   每步产出状态日志，可中断/续跑。

交互逻辑（关键界面）

  1. 导入页：拖拽/选择文件夹，显示张数与预估耗时。
  2. 复核页：左图右词表，草稿框可点选改类，证据链实时刷新。
  3. 导出页：勾选字段，生成文件并提供谱系脚本入口。

异常处理（真实风险，非虚构）

  • VLM thinking 死循环 / 超时 → 超时跳过该图，标"草稿失败，请人工"。（现状已遇）
  • 坐标不可靠/框偏 → 仅作提示，不自动落库，强制人工确认。（现状已遇）
  • CORS（file:// 源 null 被 403） → 用父窗口直连绕过，不改 Ollama。（现状已解）
  • 无 GPU / SAM 慢 → 离线后台跑，UI 不阻塞。（现状限制）
  • 用户中途退出 → 进度存 localStorage，可续跑。（现状机制）

验收标准（可量化）

  • AC-1：P0 链路在 10 张照片上 0 报错跑通（参考 [现状] 自检 20/20 基线）。
  • AC-2：无训练用户 10 分钟内完成 5 张导出（第七阶段实测）。
  • AC-3：导出 JSON 与 labelme 双向互通无丢失。
  • AC-4：照片全程不出本机（网络面板 0 外部请求）。

版本规划

  • v0.6（MVP）：P0 + FR-07 进度可视化。
  • v0.7（P1）：一致性提示、争议标记、查重。
  • v0.8（P2）：RAG 引用、移动端探索、训练数据沉淀。
