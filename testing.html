文档性质：测试方案与度量框架，非已完成测试。标注 [现状可测]（用现有 v0.5 资产即可执行）与 [需 MVP]（须 v0.6 后端建成后执行）。凡未实测的数据，一律标记为「目标值 / 待实测」，不得写成已达成。 红线：不虚构成果；现状资产不可破坏；所有「规划指标」与「实测指标」分开记录。

0. 为什么要做测试（AI PM 视角）

面试官最警惕的一句话是「我觉得体验变好了」。真正说服人的是可复现的对比数据：

「我把 10 张照片的标注，分成『纯人工组』和『VLM 草稿+人工复核组』，同一批人、同一批图，测得平均单张耗时从 X 降到 Y，标注一致性 κ 从 a 升到 b。」

这就是数据驱动的产品迭代——你不是「用 AI 写了个工具」，而是「定义了一套度量，用数据证明它有效」。本阶段给你可立即执行的测试清单 + 报告模板，让你在作品集里放的是真实数字，不是形容词。

1. 测试指标体系（四个维度）

维度回答的问题典型指标
效率（Efficiency）AI 帮用户省了多少时间？单张预处理耗时、端到端链路耗时、相对纯人工的降幅%
准确率 / 一致性（Quality）AI 出的东西准不准、人审后稳不稳？与专家金标准的吻合度、标注者间一致性 κ、草稿采纳率
可用性（Usability）非专家能不能用、愿不愿意用？任务成功率、首次完成时长、SUS/满意度评分
合规（Compliance）隐私/数据出域是否满足？外部网络请求数（应为 0）、数据落盘位置

3. 可立即执行的测试（基于 v0.5 现有资产，无需等开发）

这些现在就能做，是作品集里最早能拿到的真实数据点。

3.1 隐私合规验证（对应 AC-4）[现状可测]

  • 方法：打开 03-立面风格工作台/index.html，F12 → Network 面板，点遍全部 8 个视图与「VLM 预标注」按钮，记录外部请求。
  • 预期：0 个非 localhost 请求（Ollama 在 localhost:11434 属本地）。
  • 产出：截图 + 一句结论「照片全程不出本机，Network 面板 0 外部请求」→ 直接进作品集「隐私优先」页。
  • 诚实点：当前是 file:// 直连，仍有 CORS 绕过机制；v0.6 改后端后重测一次更干净。

3.2 预处理耗时对比（对应 H1）[现状可测]

  • 数据：04-正立面/ 下 50 张自动校正图（全部待定状态）+ 980 张清洗照片。
  • 方法：
  1. 抽 20 张原始田野照，记录「人工挑正立面 + 手动四点校正」预估耗时（可请一位同学实际做，计时）。
  2. 同一批图走现有离线脚本（EXIF 转正 + DLT 单应校正），计时。
  3. 降幅% = (人工 - 脚本) / 人工。
  • 现状可用资产：pdistance_nj.py 同类离线脚本思路、四点透视校正算法已双实现一致。
  • 产出：一张「人工 vs 工具」耗时对比柱状图（作品集可用）。

3.3 导出一致性验证（对应 AC-3）[现状可测]

  • 方法：用现有 8 份 labelme 试点（141 框 / 23 标签）做「labelme → 工作台 → 再导出 labelme」往返，核对框数/类别零丢失。
  • 产出：一致性核对表（框数、类别、坐标偏差）。

3.4 工程自检基线复跑（对应 AC-1 部分）[现状可测]

  • 方法：node --check index.html 内联脚本（或现有自检）+ 8 视图无报错 + runSelfCheck 期望 20/20。
  • 产出：自检通过截图，证明工程素养（作品集「技术落地」佐证）。

4. 需 v0.6 MVP 建成后执行的测试 [需 MVP]

这些依赖第五阶段后端 + Agent 编排完成。建好后按此执行，结果填入报告。

4.1 VLM+人审 vs 纯人工（H2）— 最核心的一组对比

  • 受试者：3–5 人（含 1–2 无建筑背景者，验证「降低门槛」）。
  • 材料：10 张已校正图（建议从 50 张自动校正图里挑）。
  • 分组：
  • A 组（纯人工）：直接在这 10 张上人工框构件 + 判风格，计时。
  • B 组（VLM 草稿+人审）：同 10 张先过 VLM 出草稿，人只改/删/确认，计时。
  • 指标：单张平均耗时（A vs B）、两组的「与专家金标准吻合度」（你作为研究者可定金标准）。
  • 结论模板：「B 组单张耗时较 A 组下降 %，与金标准吻合度保持在 %，证明 human-in-the-loop 在提速的同时未牺牲专业准确率。」

4.2 Agent 单入口降门槛（H4）

  • 任务：给无经验用户「导入 5 张图 → 校正 → 复核 → 导出谱系矩阵」，限时 10 分钟。
  • 记录：成功率（完成/总人数）、超时需要提示的次数、弃用率。
  • 对照：同一用户若用「分散工具」（脚本+labelme+手动）完成同等任务需多久/几步。

4.3 知识约束提升准确率（H5）

  • A/B：同一批图，VLM 用「裸 prompt」vs「注入 59 构件词表 + 5 类加权规则提示」两种，比较草稿框的「被人工采纳率」。
  • 指标：采纳率（人接受不改动的框 / 总草稿框）。

4.4 构件图谱 + RAG（H6，P2）

  • 在 v0.8 做：同图「固定 few-shot」vs「图谱检索增强」两种 prompt，比较草稿采纳率。

5. 测试执行手册（给你照着做）

  1. 建测试目录：06-测试与验证/，下设 原始数据/、结果记录/、截图/、报告/。
  2. 先做 3.1–3.4（现在就能交差，零开发成本）。
  3. v0.6 完成后补 4.1–4.3，邀请同学当受试者（微信/课题组群发招募即可）。
  4. 记录表统一格式（见 §6 模板），每条含：日期、受试者、数据批次、指标值、备注。
  5. 诚实标注：任何「预计/目标」值都写「目标 ≥50%，实测待填」，绝不提前成数字。
